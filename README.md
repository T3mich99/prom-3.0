# UG-OPT → Prom

Проєкт готує товари заданої категорії UG-OPT до імпорту у форматі наданого Excel.
Поточна точка входу для цієї задачі: **npm run category**.

Потрібен Node.js 24. У PowerShell відкрий папку репозиторію:

```powershell
npm ci
npm test
npm run category -- --request requests/category.json --result outputs/category-result.json
```

Codex створює request JSON за твоїм запитом. Приклад: examples/category-request.example.json.
URL-заглушку заміни точною адресою заданої категорії. Команда не обирає категорію за тебе.

Еталон templates/prom-reference.xlsx — незмінена копія наданого файла: 966 товарів,
108 колонок, 19 блоків характеристик, 341 група. Новий Excel містить лише нову партію
і збережений аркуш груп. Існуючі товари цей маршрут пропускає.

Відкрий саме цю папку як проєкт Codex і попроси обробити категорію за AGENTS.md.
Codex сам виконує operatorTasks доступними засобами, додає готові артефакти до productInputs
і повторює запуск. Коли фото подобається, вкажи область правила: товар, категорія або всі фото.
Після схвалення Codex оновлює config/photo-styles.json, зберігає еталон і фіксує зміни в Git.

У репозиторії немає підключеного живого сервісу генерації фото або автоматичного
завантаження в Drive. Категорійний процес повертає завдання, які виконує сам Codex в активній сесії. WAITING_FOR_OPERATOR
є проміжним станом. Візуальний огляд залишається обов'язковим.

Ціни використовують чинну шкалу category ROI 130%→25% і комісію 20%; ця правка її не змінює.
Нові Prom ID залишаються порожніми до імпорту. Фото мають ціль 1280×1280; наявний технічний
контракт також допускає 1254×1254. Продажі або зростання конверсії самим оформленням не гарантовані.

Повний порядок: docs/OPERATOR_WORKFLOW.md. Аудит: docs/REVIEW_2026-09-17.md.
ARCHITECTURE.md та ранні docs описують історичні етапи і не визначають поточну команду.

## Звичайний запуск

Достатньо написати Codex у цьому проєкті:

> Зроби 100 нових товарів із категорії [назва або посилання UG-OPT].

Codex сам виконує звірку кодів, відбір, контент, п'ять фото кожного товару,
публікацію фото й Excel. Перелік етапів щоразу повторювати не потрібно.
Для всієї категорії напиши «Зроби всі нові товари з категорії …».

config/category-workflow.json зберігає каталог для звірки. За замовчуванням це
вже наданий templates/prom-reference.xlsx. CLI автоматично задає вихідний XLSX;
кількість зберігається в targetCount. Ліміт застосовується ПІСЛЯ виключення
дублів і невалідних кандидатів. При нестачі доступних товарів результат містить
shortfall; готовий менший файл позначається як частковий, а не «100 виконано».

У новому середовищі потрібні доступні інструменти генерації та Google Drive.
Перевірка доступу входить у звичайний запуск. Нові зовнішні зміни магазину
стають відомі лише з актуального експорту; автоматичного зв'язку з Prom немає.

## Схвалене оформлення й запуск категорії

Стиль v3 (без моделі на фото, у назві та описі) збережено разом із наданим візуальним еталоном. Кожен SKU має власний
photoCreativeBrief; кожне з п'яти фото має окрему сцену, композицію, смисл і макет.
П'яте фото — предметне без тексту. Точні повтори задумів блокуються; візуальна
схожість додатково перевіряється Codex за справжніми зображеннями.

Запит до Codex у відкритому проєкті:

> Оброби всю категорію UG-OPT: [посилання]. Працюй за AGENTS.md і
> docs/CODEX_CATEGORY_EXECUTION.md. Сам виконай усі operatorTasks вбудованими
> інструментами Codex, без платного API. Для кожного нового товару зроби контент,
> ціну й п'ять унікальних фото за чинним стилем із config/photo-styles.json. Перевір та опублікуй фото на доступному
> хостингу й створи фінальний Excel за еталоном. Зберігай прогрес; не оголошуй
> категорію готовою, доки completion.finalWorkbookReady не стане true.

CLI зберігає результати товарів у runtime/category-state.sqlite та відновлює їх
під час повторення тієї самої команди. Request лишається джерелом нових правок;
нове поле не стирає інші збережені поля товару. Частково створені фото Codex
додатково фіксує після кожного зображення, див. інструкцію виконання.

Вбудована генерація фото враховується у загальному ліміті Codex/ChatGPT; API має
окрему оплату. Кількість товарів на тиждень не фіксована, поточний залишок дивись
у /status або usage dashboard. Джерело (перевірено 2026-09-17):
https://learn.chatgpt.com/docs/pricing#how-does-image-generation-count-toward-usage-limits

Google Drive вже визначено в config/google-drive-media.json: Prom 2.0 → PRODUCT IMAGES.
Доступ до папок перевірено, наданий еталон завантажено в STYLE REFERENCES і прочитано
назад. Товарні фото завантажує сам Codex через підключений Google Drive; команда
category:media перевіряє прямі публічні URL та SHA перед передаванням у Excel.
Для першого реального запуску залишається задати конкретну категорію UG-OPT.
