# Затверджені зміни, 2026-09-17

Користувач схвалив наданий приклад товарної інфографіки, уточнив унікальність
кожного SKU і кожного кадру у п'ятірці та попросив зафіксувати це для Codex.

- Стиль v2 і справжній наданий еталон збережені в config/ та references/photos/.
- CATEGORY_PRODUCTION тепер вимагає photoCreativeBrief перед генерацією;
  він задає окрему сцену, смисл, композицію, світло й макет кожного кадру.
- Точні повтори задумів у п'ятірці та між SKU блокуються; семантичну/візуальну
  схожість перевіряє Codex. Нові обов'язкові visual QA checks:
  sceneDistinct, layoutDistinct, productSpecificDesign. П'яте фото — без тексту.
- category:photos приймає п'ять реальних уже створених PNG без викликів API,
  перевіряє їхні SHA після огляду, байти та checklist.
- Category CLI підключає SQLite state store; відновлює прийняті артефакти й
  зливає зміни по полях. Збережений план без файлів не видається за готові фото.
- Історія концепцій зберігається між категоріями. У завдання передаються останні
  12 прикладів і шлях до повної історії; обмеження не скорочує список товарів.
- Фінальний експорт потребує готовності всієї нової допустимої категорії;
  помилки й ручне уточнення не губляться за статусом COMPLETED. Наявні в Prom
  товари пропускаються й явно відображаються у звіті.
- Збережено recovery checkpoint перед резервуванням; це не одна транзакція
  між XLSX, SQLite та файловою системою. Завершений result не перезаписується.
- Інструкція пояснює, як сам Codex виконує весь цикл вбудованими інструментами,
  зберігає кожне фото й відновлюється після фактичного блокування. Платний API
  не підключений. Автоматичне продовження після вичерпання ліміту не гарантоване.

Шкалу цін і структуру еталонного Excel ця правка не змінює.
Перевірки — автоматичні тести з фікстурами й перевірка синтаксису. Живий повний
UG-OPT → генерація → публічний хостинг → Excel запуск ще не проведено:
для нього потрібна задана категорія. Google Drive уже перевірено на читання
папок і запис еталону; прямі публічні URL товарних фото перевіряються окремо.
GitHub не змінено: результат передається оновленим ZIP для перенесення у checkout.

## Надані постачальник і папки

Користувач підтвердив https://ug-opt.in.ua/ua/ та кореневу папку Drive Prom 2.0.
У config/google-drive-media.json збережені існуючі PRODUCT IMAGES/FINAL EXCEL,
а схвалений еталон завантажено в нову STYLE REFERENCES і перевірено читанням.
Канонічний category CLI підставляє ці папки в реальні завдання публікації.

Виправлено несумісність Drive → Excel: approvedAssetRef тепер зберігає ідентичність
схваленого локального фото, а не Drive ID. SHA звіряється з локальними байтами;
category:media також перевіряє доступ без авторизації та SHA завантажених байтів.
Додано taskVersion, потрібний SQLite-черзі для збереження Drive-завдання.

Пряме посилання на еталон перевірено без авторизації: image/png, SHA відповідає
локальному оригіналу. Це перевірка доставки еталону, а не імпорту товару в Prom.

Підсумкова перевірка: npm test — 802 тести, 801 успішний, 1 пропущений,
0 помилок; git diff --check — без зауважень.

sourceFacts та коди товарів не змінюються. Фотопрофіль піднято до версії 3.

## Короткий запит і задана кількість

Користувач хоче давати лише кількість і категорію. AGENTS.md тепер прямо
трактує такий запит як повний цикл без повторних нагадувань. Додано targetCount:
100 означає 100 нових придатних товарів після реєстру, а не 100 карток сайту.
Склад партії фіксується для відновлення. Нестача відображається окремо.
Каталог для звірки зберігається в config/category-workflow.json; вихідний XLSX
CLI задає навіть для короткого request без export. Доступ до інструментів і
ліміти залишаються реальними обмеженнями; автоматичну синхронізацію Prom не додано.
