# Continuous Integration

## Scope

The CI workflow is a safety gate for the current repository behavior. It runs tests and static syntax checks only; it does not run a product export, generate images, publish products, or change an external system.

The workflow is defined in `.github/workflows/ci.yml` and runs on:

- pull requests targeting `main`;
- pushes to `development`, `development/**`, `refactor`, or `refactor/**`.

The workflow uses one quality job on `ubuntu-latest`, Node.js `24.x` (current LTS), and a ten-minute timeout. Concurrency cancels an older in-progress run for the same pull request or branch when a newer run supersedes it.

## Checks

The job fails immediately when any command returns a non-zero exit code. It runs:

1. all Node tests under `tests/`, including characterization, golden regression, and Prom workbook integration tests;
2. `node --check` for every tracked `.mjs` file;
3. `py_compile` for every tracked `.py` file;
4. PowerShell parser validation for every tracked `.ps1` file;
5. `git diff --check HEAD^ HEAD` for whitespace errors in the change being validated.

The portable test-only XLSX adapter in `tests/support/xlsx-compat.mjs` keeps the golden and integration tests runnable on a clean runner. It reads only the committed XLSX fixtures and the tracked short template; it is not production workbook code. Production scripts may still use the desktop-provided `@oai/artifact-tool`, but CI does not import or install that private runtime dependency.

## Equivalent local commands

From the repository root, run the complete gate with the configured Node runtime:

```text
node tests/quality-gate.mjs all
```

Individual commands are available when debugging a failure:

```text
node tests/quality-gate.mjs node-tests
node tests/quality-gate.mjs mjs-syntax
node tests/quality-gate.mjs python-syntax
node tests/quality-gate.mjs powershell-syntax
git diff --check HEAD^ HEAD
```

The local gate expects Node.js 24 or a compatible current Node release, Python, and PowerShell Core (`pwsh`). On Windows, the helper also accepts `py`, `python`, or Windows PowerShell when they are available. Set `PYTHON` or `POWERSHELL` to an executable path when a host uses a non-standard command name.

The baseline run in this phase completed in roughly one second with the portable XLSX adapter. The CI timeout is intentionally more generous for a clean hosted runner and for parallel test-runner startup.

## Intentionally excluded

CI does not run:

- production builders or repair scripts;
- live UG-OPT or BigDrop requests;
- live Prom.ua access or publication;
- Google Drive reads, permission changes, uploads, or deletes;
- paid AI image generation;
- supplier-system mutations;
- local production workbooks, credentials, Downloads/Desktop paths, or ignored `outputs/` data;
- `tests/golden/extract-real-goldens.mjs`, which is a deliberate local maintenance utility for reviewing historical workbooks rather than a CI test.

Those boundaries keep the workflow deterministic and free of external side effects. Live integrations remain documented as future mocked or manually verified targets in `docs/TEST_BASELINE.md` and `docs/GOLDEN_BASELINE.md`.

## Interpreting failures

- A Node test failure means a characterized contract, golden snapshot, or portable workbook contract changed or is incomplete.
- A golden failure means observable historical behavior changed. Do not update a golden fixture automatically; inspect the production diff and obtain explicit business/engineering review before changing `snapshot.json` or `pricing-cases.json`.
- A syntax failure indicates invalid source syntax in the reported language.
- A whitespace failure comes from `git diff --check` and should be fixed in the changed file.

CI is a gate, not a claim that current business behavior is correct. The migration intentionally preserves conflicting pricing, identifier, category, content, and photo policies until a later reviewed extraction phase.

## Portability and governance

The workflow installs no application dependencies and relies only on committed source and fixtures plus the hosted Node/Python/PowerShell runtimes. It has read-only repository permissions. No production file is modified by this phase, and no golden file is ever regenerated by CI.
