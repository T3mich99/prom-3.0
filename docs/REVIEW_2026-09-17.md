# Аудит наданого архіву та виправлення

Джерела: product-automation-main.zip і наданий export-products-13-09-26_22-18-14(1).xlsx.
Live GitHub був недоступний. Це перевірка архіву, не твердження про поточну віддалену main.

## Підтверджені причини непослідовного процесу

1. В архіві немає AGENTS.md або README.md. Вхід для оператора не визначений.
2. PHOTO-MASTER-SPEC.md називає себе єдиною політикою, забороняє логотипи та задає
   інші ролі файлів. PHOTO_PRODUCTION_CONTRACT.md і актуальний код зберігають бренд.
3. Старі scripts/ і excel-work містять інші фото- та контентні рецепти. Наприклад,
   make-hair-reference-style-v3.mjs вставляє номери кадрів та конкретні характеристики
   фена незалежно від переданого товару. Ці скрипти не мають бути довільним fallback.
4. npm run production викликає end-to-end-production-runner, тоді як потрібний
   category-production-runner існує, але не має CLI. Перший маршрут використовує
   append writer; другий уже має delta writer.
5. Категорійний runner передає productionArtifact, а delta registry перевіряє
   product.productCode до витягування коду з артефакту. Також губляться характеристики
   артефакту і не прочитуються канонічні categoryId/categoryName у перевірці категорії.
6. Delta writer не перевіряє повтори коду всередині нової партії, може створити
   файл без товарів і повернути часткові EXPORTED-статуси після помилки до запису.
7. Немає окремого збереженого профілю схвалених стилів із версіями та референсами;
   noDarkHalos відсутній у visual checklist.

## Що змінено

- Додані AGENTS.md, README.md, operator runbook, приклад request і npm run category.
- Точна копія Excel та фізична схема з SHA-256 включені в templates/.
- CLI використовує існуючий category runner, bootstrap та registry, зберігає JSON
  результат і відбитки шаблону/правил, резервує експортовані коди. Див. обмеження
  recovery checkpoint у OPERATOR_WORKFLOW.md.
- Стилі зберігаються в config/photo-styles.json; підтримуються global, families,
  точні URL categories і products. Еталони хешуються. Профіль включений у план,
  готовий prompt — у operator task. Застарілі/підмінені профілі блокуються.
- Доданий обов'язковий noDarkHalos; виправлена суперечлива головна фотоінструкція.
- Delta export переносить характеристики, правильно отримує код і категорію,
  перевіряє обов'язкові поля, ціну та дублікати. Запис спочатку перевіряється у staging.
  Аркуш груп і джерело зберігаються, source SHA контролюється до/після операції.
- Категорійний runner не створює порожній результат і явно повідомляє export review.
- Test gate працює також у розпакованому ZIP без .git.

## Що не встановлено або не виконано

У цьому архіві немає наданого користувачем конкретного невдалого фото з чорним
ореолом і повного журналу його генерації. Точну причину артефакту на рівні пікселів
не встановлено. Заборона в prompt і ручний QA зменшують ризик повтору, але не є
автоматичним детектором чорних ореолів або гарантією якості кожної генерації.

Фото для нової категорії не генерувалися, live UG-OPT/Drive/Prom цикл не запускався,
імпорт у магазин і GitHub push не виконувалися. Нова категорія користувачем ще не задана.
Схвалені приклади не вигадувались. Ціноутворення, старі golden fixtures і правила
UA/RU не переписувались. Поточна шкала ROI відрізняється від старих 90% у переписці.

## Перенесення змін

Розпакуй архів як окрему копію для огляду. У робочому Git checkout створи гілку
і перенеси змінені/нові файли, зберігши локальні незакомічені правки. Перелік є у
CHANGESET.txt. Не замінюй credentials, .env, runtime або .git. Після npm ci і npm test
перевір diff, зроби commit та push/PR. Новий чат Codex відкривай у цій актуальній папці.


## Перевірка цієї версії

- Повний Node suite: 789 тестів, 788 пройдено, 0 помилок, 1 пропущено.
- Синтаксис: 204 JavaScript-модулі пройшли node --check.
- git diff --check: без помилок.
- Нові регресійні перевірки охоплюють справжній 108-колонковий шаблон, збереження
  груп/джерела, перенесення характеристики з productionArtifact, дублікати партії,
  порожню партію, обов'язкову одиницю, невірну ціну, профілі та stale fingerprint,
  відхилення ореолу й запуск category CLI з реальним bootstrap шаблону.
- Мережеві генерація, публікація фото й імпорт у Prom не тестувалися.

Архів містить повну виправлену папку та review-changes.patch поруч. Patch призначений
для того стану, який був у наданому ZIP. У робочій гілці спочатку виконай
`git apply --check <шлях-до-review-changes.patch>`; застосовуй лише якщо перевірка
пройшла. Якщо код вже змінився, Codex має порівняти й інтегрувати зміни без примусового
перезапису. .git, node_modules, runtime, credentials і .env в архів не додаються.
